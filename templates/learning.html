Theory & Concepts

This module provides a comprehensive theoretical and practical foundation on cryptographic hashing, fuzzy hashing (ssdeep and TLSH), file similarity heuristics, and their appropriate applications in cyber forensics, malware analysis, incident response, and threat intelligence.

1. What is Hashing?

A hash function is a deterministic mathematical algorithm that maps arbitrary-length input data (such as a file, string, or binary stream) to a fixed-size digest. Regardless of whether the input is 10 bytes or 10 gigabytes, the resulting output digest has a constant bit length.

Cryptographic Hashing

  • Algorithms: MD5 (128-bit), SHA-1 (160-bit), SHA-256 (256-bit), SHA-3
  • Core Property: Strict Avalanche Effect — flipping a single bit alters ~50% of output bits.
  • Purpose: Integrity verification, digital signatures, non-repudiation, tamper detection.
  • Forensic Limitation: Cannot determine if two modified files share common ancestry or code.

Fuzzy Hashing (Similarity Hashing)

  • Algorithms: ssdeep (CTPH), TLSH (Locality Sensitive Hashing), sdhash
  • Core Property: Locality Sensitivity — small input modifications produce proportional digest changes.
  • Purpose: Malware variant discovery, patch diffing, code reuse identification, artifact clustering.
  • Forensic Strength: Evaluates structural similarity even across recompilations and minor mutations.

2. Avalanche Effect vs. Locality Sensitivity

Scenario Cryptographic Hash (SHA-256) Fuzzy Hash (ssdeep / TLSH) Investigation Outcome
Identical Files Matches exactly (100%) Matches exactly (Score: 100) Exact identical duplicate file.
1 Byte Modified 0% match (completely different digest) ~99% match (nearly identical digest) Fuzzy hashing detects direct derivation / minor tweak.
Recompiled / Patched Binary 0% match (avalanche breakdown) 70% - 95% match Identified as likely variant belonging to same family.
Unrelated File 0% match 0% match (score 0 / high distance) Correctly classified as unrelated.

3. How Fuzzy Hashing Algorithms Work

ssdeep (Context-Triggered Piecewise Hashing - CTPH)

Designed by Jesse Kornblum based on spamsum (Dr. Andrew Tridgell). Instead of dividing a file into fixed-size blocks, ssdeep calculates a rolling hash (Adler32-style window) across byte streams.

  1. A rolling 7-byte checksum triggers a block boundary whenever its value modulo the block size equals a designated trigger.
  2. For each block triggered, a traditional hash (FNV) is computed and converted to a single Base64 character.
  3. The final ssdeep hash format is: blocksize:hash_string1:hash_string2.
  4. Comparison uses Levenshtein edit distance on the matching block-size strings.

TLSH (Trend Micro Locality Sensitive Hash)

Published in 2013 by Jonathan Oliver, Chun Cheng, and Yanggui Chen. TLSH processes 50+ byte sequences by constructing byte-pair tri-gram frequency distributions across 256 buckets.

  1. Computes quartile thresholds (Q1, Q2, Q3) of byte-triplet frequency buckets.
  2. Constructs a 70-character or 134-character hex digest storing length, quartile ratios, checksum, and 2-bit bucket classifications.
  3. Comparison calculates a numeric distance metric (0 = identical, 300+ = completely distinct).

4. Real-World Cybersecurity & Forensics Applications

🦠 Malware Variant Clustering

Malware authors frequently recompile, alter command strings, or change IP addresses. Fuzzy hashing clusters variants into families without requiring prior disassembly.

🚨 Incident Response Triage

During live breach responses, analysts match dropped staging scripts, staging DLLs, or compromised binaries against known threat-actor toolkits.

🔍 Forensic Evidence Correlation

Correlates artifacts across multiple seized endpoint drives even when filenames, paths, or file metadata timestamps have been wiped or altered.

📦 Software Lineage & Patch Diffing

Detects whether third-party open-source libraries or vulnerable vulnerable components have been bundled inside proprietary compiled software.

5. Limitations, False Positives & Why Fuzzy Hashing is NOT a Malware Detector

A critical principle of digital forensics is that similarity does not prove malice. Fuzzy hashing evaluates byte structural proximity, NOT behavior or intent.

Common False Positives

  • Two benign programs built with the same Visual Studio C++ runtime runtime libraries.
  • Files sharing massive static resources (embedded bitmaps, icons, large XML schemas).
  • Binaries packed using standard UPX or PyInstaller wrappers.

Common False Negatives

  • Polymorphic or metamophic malware engines that re-encrypt or randomize binary structure.
  • Different compiler optimizations (e.g., GCC -O0 vs -O3) that heavily rearrange functions.
  • Small files under 50-100 bytes where insufficient entropy exists for piecewise sampling.
Investigative Protocol: A high similarity score should always trigger secondary forensic workflows: static reverse engineering, dynamic sandboxing, YARA matching, behavioral inspection, and threat intelligence lookups.
